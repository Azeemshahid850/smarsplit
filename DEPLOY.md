# Deploying SmartSplit & ExpenseAI

Two pieces: **MongoDB Atlas** (database) and **one Render web service** that runs the API
*and* serves the built React app from the same URL.

Why one service and not Vercel + Render: `*.vercel.app` and `*.onrender.com` are different
sites, so the browser blocks the `SameSite=Strict` refresh cookie and every reload signs the
user out. Serving the client from Express keeps everything on one origin: the cookie is
first-party and CORS never applies.

---

## 1. MongoDB Atlas

1. Create a free **M0** cluster at <https://cloud.mongodb.com>.
2. **Database Access** → Add user, e.g. `smartsplit`, password auto-generated. Copy it.
3. **Network Access** → Add IP address → **Allow access from anywhere** (`0.0.0.0/0`).
   Render's outbound IPs are not fixed on the free tier.
4. **Connect → Drivers** → copy the connection string and add the database name:

```
mongodb+srv://smartsplit:<password>@cluster0.xxxxx.mongodb.net/smartsplit?retryWrites=true&w=majority
```

## 2. Render — from the Blueprint

The repo carries `render.yaml`, so Render reads every setting from it.

1. Sign in at <https://dashboard.render.com> with the GitHub account that owns the repo.
2. **New → Blueprint** → select the repo → **Apply**.
3. It asks for one value: paste the Atlas string into `MONGO_URI`.
4. Wait for the first deploy, then open `https://<service>.onrender.com`.

What the Blueprint sets up:

| Setting | Value |
|---|---|
| Build | `npm --prefix server ci --omit=dev && npm --prefix client ci --include=dev && npm --prefix client run build` |
| Start | `npm --prefix server start` |
| Health check | `/api/v1/health` |
| Region / plan | Singapore / Free |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | generated by Render, different from each other |
| `CLIENT_URL` | not needed — falls back to Render's own `RENDER_EXTERNAL_URL` |
| Client API URL | not needed — production builds call the relative `/api/v1` |

### Optional environment variables (Render → service → Environment)

| Key | Without it |
|---|---|
| `VISION_API_KEY` | receipt OCR runs on Tesseract instead of the vision model |
| `ADMIN_EMAILS` | comma-separated emails of app admins — they get the Admin page and may add stores and prices on the Price book page (optional — unset means nobody is an admin and the book is read-only) |
| `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | receipt images are stored inline as data URLs |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `MAIL_FROM` | nothing is emailed; invite links are shared by copy or WhatsApp, reset links go to the server log |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | no Google sign-in button (see step 5) |

## 3. How updates go live

`git push` to `main` is the whole release process:

1. GitHub Actions (`.github/workflows/ci.yml`) runs the full server test suite and a client build.
2. Render's `autoDeployTrigger: checksPass` waits for that to go green, then rebuilds and deploys.
3. A red build never reaches the live site; fix it and push again.

Watch it under the repo's **Actions** tab and Render's **Events** tab. If Render ever rejects
`autoDeployTrigger`, replace that line in `render.yaml` with `autoDeploy: true` (deploys on every
push without waiting for the tests).

## 4. Seed the demo data

From your machine, pointed at the production database:

```bash
cd server
MONGO_URI="<the Atlas string>" npm run seed
```

Creates: five users (**azeem@demo.pk / Demo1234**), the Murree Trip group with 7 expenses,
a Flat 3B group, 12 personal transactions, 4 budgets, 3 price-matched receipts, and the
100-product price book.

**The seed wipes every collection first.** Never run it against a database with real data.

---

## 5. Google OAuth (optional)

1. Google Cloud Console → **APIs & Services → Credentials → OAuth client ID → Web application**.
2. Authorised JavaScript origins: your Render URL.
3. Authorised redirect URIs: `https://<service>.onrender.com/auth/google/callback`.
4. Add `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` on Render, plus `VITE_GOOGLE_CLIENT_ID`
   (same value — Vite reads it at build time), then redeploy.

## Notes and gotchas

- **Render free tier sleeps** after ~15 minutes idle; the first request afterwards takes
  ~30 seconds. The server pings its own `/api/v1/health` every 10 minutes when Render's
  `RENDER_EXTERNAL_URL` is present, which keeps it awake. Still open the site a minute
  before demoing in case it was redeployed.
- **Rate limits are per IP.** A classroom or office shares one, so the auth limits are sized
  for a room (50 sign-ups, 60 logins, 300 refreshes per 15 min). If a demo audience still
  sees "Too many attempts", raise them in `server/src/routes/auth.js`.
- **The recurring-transactions cron** (`0 2 * * *`) only fires while the service is awake. On
  the free tier, treat it as best-effort.
- **Never commit `.env`.** It is in `.gitignore`; keep it that way.
- **Rotating a JWT secret signs everybody out** — that is the intended behaviour.
